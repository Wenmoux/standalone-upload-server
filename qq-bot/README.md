# QQ Bot

QQ Bot 提供书名/作者/标签搜索、分页、书籍详情以及 TXT/EPUB 下载。业务数据只通过 `server-pg:3100` 的 Bot API 读取。

## 开放平台准备

1. 在 QQ 开放平台创建机器人并启用单聊、群聊能力。
2. 为机器人申请 `GROUP_AND_C2C_EVENT` 事件权限。
3. 使用后台“QQ Bot”页面填写 AppID 和重置后的 AppSecret，设置允许/屏蔽平台及屏蔽标签。
4. 保存后约 15 秒内进程会自动连接；无需重启容器。

## 用户交互

- 直接发送书名、作者或 `#标签` 搜索；结果只显示至少已有一章正文缓存、可以实际下载的书籍。
- `下一页`、`上一页` 翻页。
- 发送结果序号查看详情。
- `TXT 1` 导出本页第 1 本。
- `EPUB 1` 选择与 Telegram 相同的 EPUB 样式。
- `签到` 领取与 Telegram 相同的每日签到、连签和书卷经验奖励。
- 群聊中需要先 @机器人。

菜单、搜索结果和书籍详情与 Telegram 使用同一份书卡字段模型；QQ 端只使用客户端稳定渲染的块级标题、分隔线及蓝/灰按钮色阶，作者、平台、章节等业务字段保持纯文本，避免部分客户端裸露行内 Markdown 标记。结果选择、翻页、TXT/EPUB 和样式选择均使用内嵌键盘；若机器人账号尚未开放相应权限，消息发送器自动降级为同内容的纯文本命令。

主面板只显示账户摘要、搜书、签到和帮助；命令说明收进独立帮助页。搜索页按两列书名按钮选书，详情页用紧凑信息条呈现缓存、章节、热度与反馈，EPUB 样式以两列按钮选择；导出生成中、完成和失败分别使用独立状态卡。

通过书号直接查看纯元信息书籍时仍会展示详情，但不会显示 TXT/EPUB 假入口。文件投递遵循 QQ 官方预上传、分片 PUT、分片确认、合并和 `file_info` 消息流程；内部代理或 BDH 临时错误会按阶段自动重试，最终错误会标明失败阶段与错误码。

QQ 被动回复存在时效和次数限制，导出过程会压缩为进度、文件、完成状态三次回复。单文件超过 QQ 官方 200 MB 上限时会明确拒绝。
