# EPUB 模板库与自定义导出

本文描述当前可运行的 EPUB 模板库、Bot 自定义交互和从样式知识库接入新模板的边界。运行事实以 `services/epub-style-config.js`、`bot/epub-styles/`、`assets/epub-templates/` 与测试为准。

`services/epub-style-config.js` 是模板名称、说明、公开状态和能力的唯一注册表。Telegram、QQ、Admin 配置和 EPUB 生成器都消费这一事实源；`crane` 只保留旧配置兼容，不进入用户模板库。

## Bot 交互

Telegram 与 QQ 都提供两级流程：

```text
书籍详情
  -> 制作 EPUB
  -> 模板库
       -> 点击成品模板：立即创建导出任务
       -> 自定义生成
            -> 选择底板
            -> 开关制作说明
            -> 开关章头装饰（仅支持的模板显示）
            -> 确认生成
       -> 模板工坊
            -> 循环选择章题/分卷/简介/装饰
            -> 确认生成
```

自定义配置只有三个用户级字段：

```json
{
  "styleId": "style2",
  "includeColophon": false,
  "showTopImage": true
}
```

模板工坊在同一配置中增加受控组件选择：

```json
{
  "styleId": "studio",
  "includeColophon": true,
  "showTopImage": false,
  "studio": {
    "chapter": "yunwen",
    "volume": "qinglan",
    "intro": "huihan",
    "ornament": "sanxing"
  }
}
```

- `styleId` 必须是公开模板，兼容模板不能通过回调数据绕过白名单。
- `includeColophon` 控制是否写入制作说明 XHTML。
- `showTopImage` 只对声明 `chapterArt: optional` 的模板生效；不支持章头图的模板会强制归一为 `false`。
- Telegram 自定义状态编码在受控 callback data 中，不依赖进程内会话；所有回调保持在 64 字节限制内。
- QQ 自定义状态按用户和会话隔离，并在取消、换书、重新搜索或任务结束后清理。

四类组件可形成 `6 × 4 × 3 × 4 = 288` 种组合。分卷组件仍只消费真实非空分卷记录；章题只使用来源标题中实际存在的章号，缺少章号时直接显示完整标题且不保留空行；朱签终卷只在最后一个正文页插入“全书完”。云纹托题条件打包《云空行》的云纹图，其余组件使用项目已有楷体和兼容字体回退。

## 持久任务与恢复

Telegram 创建 EPUB 任务时同时保存 `epub_style_id` 和规范化后的 `epub_config`。任务幂等键包含模板 ID、制作说明开关、章头开关和模板工坊 4 字符状态，避免不同自定义方案被折叠为同一任务。

Bot 重启后，`task-schedulers.js` 从 `system_jobs.input_json.epub_config` 恢复原配置。群聊转私聊续接也保留同一配置，不会退回后台默认模板。实际构建时，用户级三个字段覆盖后台全局默认，其余受控模板参数仍继承后台配置。

## 知识库接入边界

《EPUB 样式表知识库》是设计与兼容性参考，不是可直接执行的模板包。本次递归扫描下载目录并读取 EPUB 内部 OPF、CSS、XHTML、字体和图片清单，不再只按文件名判断。精确匹配并接入《1870叛逆者的告白书》《麒麟》《云空行·全四册》《宠魅》；`[K]这该死的求生欲1.0[望三山][BL].epub` 的 `fonts.css` 与知识库第二套同属 `[K]` Kindle 模板家族，已接入其可泛化章题和简介；《大唐辟珠记》《情蛊》《食南之徒》等“丹青制作”样书与知识库第四套同属 `fonts.css + style.css` 双端模板家族，已接入不依赖固定插画的章题、分卷和分隔组件。知识库中的《显微镜下的大明》原文件、第五至第七部分原文件仍未在下载目录精确出现，不能声称已做 1:1 成品复刻。Markdown 中的其他 CSS 片段只有在以下组成全部齐备后，才能注册成可生成模板：

1. 完整且可再分发的 CSS，而不是节选选择器。
2. 封面、制作说明、简介、分卷和章节所需的 XHTML 骨架。
3. CSS/XHTML 引用的图片和字体资源，以及明确的媒体类型。
4. 动态书名、作者、简介、卷名、章名和正文的转义位置。
5. OPF manifest、spine、NCX 和全屏属性所需的插件声明。
6. 无分卷、空简介、无封面、数字标题和缺失资源的回退行为。
7. 构建器、模板选择器和真实 ZIP 内容的回归测试。

缺少图片或字体的知识库条目可以先作为“参考模板”分析，但不得设置 `public: true`。这是为了防止 Bot 暴露一个可点击却必然缺图、缺字体或生成无效 EPUB 的入口。

## 新模板接入顺序

1. 将完整 CSS/XHTML 放入 `assets/epub-templates/`，静态资源放入 `bot/epub-styles/assets/` 或模板专属资源目录。
2. 在 `bot/epub-styles/` 创建插件，声明 CSS、页面渲染器、资源、目录和全屏能力。
3. 在 `bot/epub-styles/index.js` 注册插件。
4. 在 `services/epub-style-config.js` 登记模板能力，首次接入保持 `public: false`。
5. 补充 Admin 同源预览和 EPUB ZIP 内容测试。
6. 通过文档、编码、Schema、Lint 和测试门禁后，将模板切换为 `public: true`；成品模板保持 `direct: true` 自动进入直选列表，组件型模板使用 `direct: false` 和专属入口。

## 兼容原则

- 当前输出仍为 EPUB 2；知识库中的 EPUB 3 弹出脚注不能只靠复制 CSS 接入。
- 多看专有属性可以作为增强，但正文、目录和基础阅读必须在普通 EPUB 阅读器中可用。
- 不按章节数组位置生成章号；只拆分来源标题本身已有的章号。
- 真实非空分卷才生成分卷页，不注入默认“正文卷”。
- 字体和图片必须进入 manifest，CSS/XHTML 不得引用未打包资源。
- 用户自定义只能修改注册表声明为安全的字段，不接受 Bot 端任意 CSS 或 XHTML 输入。
